# Agent Briefs

Store bounded execution briefs derived from approved requirements.

Each brief must state objective, requirement IDs, canonical files, allowed scope, prohibited legacy stacks, dependencies, acceptance criteria, verification commands, evidence to return, and out-of-scope work. One brief should produce one reviewable change set. Resolve material ambiguity in requirements or decisions before implementation begins.

Lifecycle: `draft → ready → in-progress → completed`. `ready` requires approved requirements and adopted applicable decisions; `in-progress` names an owner and start date; `completed` requires returned verification evidence. Active work may move to `blocked` and resume to `in-progress` with the blocker recorded. Any non-completed brief may become `cancelled` with a reason.
