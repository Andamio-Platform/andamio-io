# Audits

Store dated, reproducible assessments of the current canonical landing experience.

Every audit must include scope, canonical commit, environment and viewport, method, evidence, severity, affected audience, finding owner, and recommended next step. Separate observed facts from interpretation. Link findings to requirements or decisions; do not edit legacy landing stacks to resolve canonical findings.

Lifecycle: `planned → in-progress → complete → triaged → closed`. `complete` requires reproducible evidence; `triaged` requires every finding to be accepted, rejected with rationale, or linked to a requirement or adopted decision; `closed` requires disposition evidence. Mark an invalidated audit `superseded` and link its replacement.
