# Requirements

Translate verified research and audit findings into testable outcomes.

Each requirement must have an ID, status, issuer-primary or developer-secondary audience, source evidence, user outcome, acceptance criteria, priority, dependencies, and explicit non-goals. Cover content, accessibility, responsive behavior, performance, SEO, analytics/privacy, and failure states where applicable.

Requirements describe outcomes and constraints. Implementation details belong in [implementation](../implementation/README.md) unless a recorded decision makes them mandatory.
