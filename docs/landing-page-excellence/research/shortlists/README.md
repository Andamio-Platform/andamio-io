# Research Shortlists

Shortlists contain only candidates that passed the [methodology](../methodology.md) inclusion gates and scoring rubric.

Each shortlist must name its `as_of` date, decision supported, category and phase freshness windows, effective window, candidate counts, ranked records, score breakdowns, risks, recommendation, and rejected alternatives.

Immediately before scoring, apply the [mechanical freshness procedure](../methodology.md#mechanical-verification): use the shortlist `as_of` date, set the phase window to 45 days, resolve the category window (`github-ai=30`, `ui-ux=180`, `other=90`), and require every material citation to be reachable, `supports`, and no older than the smaller window. Report total, passed, stale, unreachable, and unsupported counts. Return failures to `researching` and exclude them from candidate count, ranking, and scoring.

Research records enter a shortlist only through `verified → shortlisted`; a recommendation may later become `adopted`, `rejected`, or `superseded` as defined by the research lifecycle. A shortlist recommends; it does not authorize implementation. Adoption requires approved requirements and every applicable material decision to be `adopted`.
